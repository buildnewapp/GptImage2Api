# 创始人关怀与召回邮件

复用已有邮件发送和后台邮件记录。英文模板由父项目维护，产品资料由子项目提供。默认关闭，不需要新增队列或独立服务。

## 发送规则

| 场景       | 计时起点                         | 节点    | 内容                               |
| ---------- | -------------------------------- | ------- | ---------------------------------- |
| 下单未付款 | 成功生成支付链接                 | 1 小时  | 询问付款是否遇到问题、是否需要帮助 |
| 下单未付款 | 同上                             | 6 小时  | 优惠码、帮助、产品介绍             |
| 首次付费   | 服务端确认支付成功               | 1 小时  | 感谢购买、询问使用是否需要帮助     |
| 注册未付费 | 首次完成邮箱验证；OAuth 为注册时 | 2 小时  | 了解用户目标、询问是否需要帮助     |
| 注册未付费 | 同上                             | 24 小时 | 优惠码、询问未购买原因             |

- 每个用户每个节点最多提交一次，反复创建订单不会重复启动同一节点；复购和续费不重复发送首次付费关怀。
- 下单后退出注册流程；付款后退出全部未付费流程。发送前重新检查用户和订单状态。
- 未验证、匿名、被封禁、人工暂停的用户不发送。已有付费历史、有效/试用订阅、订单处于 `processing` 时不发送未付费召回；已退款不发首次付费关怀。
- 相邻未付费召回至少间隔 4 小时，避免注册后立即下单造成连续打扰；付费关怀不受此间隔限制。
- 定时任务晚到时只发送当前阶段：下单帮助在 1～6 小时、下单优惠在 6～48 小时、注册帮助在 2～24 小时、注册优惠在 24～72 小时、付费关怀在 1～72 小时内有效。不会在停机恢复后集中补发过期节点。
- 首次真正运行时保存启用时间，只处理此后开始的事件，不群发历史用户。关闭再开启保留原启用时间。

这些邮件是自动发送的创始人口吻邮件。收件人回复到创始人邮箱，后续由人工处理；后台用户详情的「自动关怀邮件」可以暂停/恢复该用户。暂停也包括付费关怀；恢复后仍遵守节点时间窗口。

## 每个子项目的配置

沿用当前项目的 `config/site.ts` 中的名称、URL，以及 `i18n/messages/en/common.json` 的 `Home.description`。不在父项目模板里写死产品名称。

```env
RECALL_ENABLED=true

# 留空默认 Jame、jame@站点域名（去除 www.）
RECALL_FOUNDER_NAME=
RECALL_FOUNDER_EMAIL=

# 已在支付系统创建且可实际兑换的优惠码与英文优惠说明
RECALL_COUPON_CODE=
RECALL_COUPON_DESCRIPTION=

# 可选；默认站点的 NEXT_PUBLIC_PRICING_PATH 或 /pricing
# 如需自动携带折扣，可填写已有的优惠结账链接
RECALL_COUPON_URL=

# 留空默认项目根目录的 org_guide.md，也支持相对/绝对路径
pdf_md_path=
```

只有优惠码和说明都非空，才发送两个优惠节点。说明应包含实际折扣、适用套餐和有效期；系统不创建优惠码、不推断金额或有效期。跨注册/下单流程时复用此前已发邮件的优惠信息，不自动叠加折扣。发件人和 Reply-To 都使用创始人邮箱。

各独立产品使用各自配置和数据库。如果多个域名共用同一套用户/订单数据库，只在一个负责该用户库的站点启用召回；当前数据表没有用户所属产品字段，不能按域名拆分收件人。

## PDF：提前生成，随子项目部署

```env
pdf_md_path=/Users/syx/WebstormProjects/seo-submit/tikdek.com/org_guide.md
```

在子项目根目录执行：

```sh
pnpm emails:generate-pdf
```

输出为 `public/emails/product-guide.pdf`。正文来自 Markdown，封面补充当前产品名称、英文介绍，结尾附创始人联系方式。双语资料存在 `## English` 等独立英文标题时，只取该段；其他资料请使用英文正文。支持标题、段落、列表、链接和表格文字；不下载外部图片。

- Markdown 不存在：正常跳过，不生成文件，也不删除已有 PDF。
- 生成错误：退出并报错，保留上一次成功的 PDF。
- 发送时读取部署目录里的 PDF，不读取 Markdown，也不运行生成脚本。
- 有有效 PDF：五种邮件均携带同一份附件，并在正文提及；无文件、读取失败或超过 3 MiB：照常发送，不提附件。
- PDF 内容更新后重新运行脚本，将 PDF 提交在对应子项目并部署。父项目只维护脚本，不提交任何子产品的 PDF。需要停用附件时删除该子项目的输出 PDF 后部署。
- Docker 部署需把 `public/` 带进运行镜像；生产环境不需要这台电脑上的 Markdown 绝对路径。`public` 中的资料会公开访问，请使用公开的产品指南。

## 数据库与定时触发

新增迁移 `0049_founder_recall.sql`：用户增加关怀计时、暂停字段，订单增加结账开始和支付确认时间。既有已验证用户回填原注册时间，防止更新个人资料时被当作新用户。不需要 seed。

1. 先检查目标数据库的待执行迁移，再执行 `pnpm db:migrate`，部署新代码。
2. 设置 `RECALL_ENABLED=true`、既有 `CRON_PWD`，按需填写优惠与创始人配置。
3. 调用一次实际接口建立启用时间，然后每 5 分钟调用一次。由现有服务器/外部定时工具调度，不使用 Cloudflare Worker 定时器。

```sh
curl --fail-with-body \
  -H "Authorization: Bearer $CRON_PWD" \
  "$NEXT_PUBLIC_SITE_URL/api/cron/recall"
```

只预览候选用户和节点，不发信、不写邮件记录、不建立启用时间：

```sh
curl --fail-with-body \
  -H "Authorization: Bearer $CRON_PWD" \
  "$NEXT_PUBLIC_SITE_URL/api/cron/recall?dryRun=1"
```

未首次启用时预览为空是正常行为。5 分钟调度下，邮件通常在节点到期后约 0～5 分钟发送；跨流程间隔可能进一步推迟未付费召回。

运行状态借用 `cache_db` 的 `email_recall/runner` 记录，保存启用时间和短期锁，不新增任务表。一次最多尝试 50 封、扫描约 45 秒，并发调用返回 `busy`。适用于当前小用户量；后续增长时再考虑队列。

## 排查与验证

后台「邮件记录」查看 `recall-*` 模板。复用既有幂等发送机制，失败、超时或发送结果未知不会自动重试，避免重复打扰；在邮件记录和通道后台核对后人工处理。

```sh
pnpm exec tsx --test lib/email/email.test.ts lib/email/recall/recall.test.tsx lib/admin/system-emails.test.ts
pnpm exec tsc --noEmit --incremental false
```

验收路径：新用户验证邮箱 → 等待/预览注册节点 → 创建结账链接切换下单节点 → 支付 Webhook 写入 `paid_at` 后只剩付费关怀 → 重复触发不重复发送；另检查人工暂停、缺失 PDF、优惠未配置时的跳过行为。
